# Полная матрица backpressure от 21.10.2026

Четыре режима выполнены на одном образе приложения и с одной версией
модели MLflow (`cfpb-complaint-classifier@champion`, фактическая версия 1).
Во всех режимах обработаны 800 одинаковых синтетических жалоб. Данные
получены на реальных RabbitMQ 4.1.8 и PostgreSQL 16. Docker имел 2 ГБ
памяти и два CPU.

## Условия

- E1: без лимита очереди и prefetch, один воркер.
- E2: ready ≤ 20, prefetch 2, один воркер.
- E3: без лимита очереди и prefetch, два воркера.
- E4: ready ≤ 20, prefetch 2 на воркер, два воркера.
- На воркер два слота и два потока, задержка inference 0,2 с.
- MLflow работал при загрузке модели, затем штатно останавливался до
  измерения нагрузки во всех четырёх режимах. После каждого опыта он
  запускался снова. Оба воркера проверялись на протяжении опыта.

Первые 20 секунд помечены `phase=load`, далее тот же конечный файл
дренировался. Источник читает по одной записи и при отказе брокера
повторяет ту же задачу с задержкой. HTTP-пробы учитываются отдельно.

| Режим | Max ready | Max unacked | Источник, задач/с на 5–20 с | Batch-завершения/с | p95 задачи | Коммиты воркеров |
| --- | ---: | ---: | ---: | ---: | ---: | --- |
| E1 | 0 | 775 | 0, файл опубликован | 9,28 | 82,56 с | 817 |
| E2 | 20 | 2 | 8,56 | 8,49 | 2,61 с | 809 |
| E3 | 0 | 774 | 0, файл опубликован | 18,41 | 41,56 с | 409 + 408 |
| E4 | 20 | 4 | 17,76 | 17,76 | 1,50 с | 403 + 404 |

Max — максимум секундных отсчётов Management API, а не гарантированный
мгновенный пик. Скорости рассчитаны по разности накопленных счётчиков
на доступных отсчётах 5–20 с; готовые задачи включают только batch.
В E1/E3 источник успел завершить файл до этого окна. В E2/E4 источник
продолжал публикацию и его скорость согласовалась с обработкой.
В E4 он ускорился примерно в 2,08 раза относительно E2.

## Проверка сохранности и ответа API

После дренирования во всех режимах 800 уникальных batch-задач имели по
одному результату; основная очередь и DLQ пусты. API-проб было по 17:
E1 — 17 ответов 202; E2 — 9 ответов 202 и 8 ответов 503; E3 — 17
ответов 202; E4 — 7 ответов 202 и 10 ответов 503. У всех 503 был
`Retry-After: 1`. p95 времени ответа 503 — 25,1 мс в E2 и 197,5 мс
в E4. Память источника E2/E4 достигала 45,60/61,58 MiB; при 800
задачах она не росла вместе с очередью.

## Файлы

- `input.csv` — входной файл; SHA-256 находится в `environment.json`.
- `environment.json` — версия Git, хеши исходников и условия Docker.
- `E*/config.json` — настройки, образ, версия модели, баланс и число
  коммитов каждого воркера.
- `E*/source.csv` — подтверждения и отказы публикации со стабильным task_id.
- `E*/samples.csv` — временные ряды ready, unacked, памяти и скоростей.
- `E*/tasks.csv` — результаты, времена inference, обработки и задачи.
- `E*/api.csv` — статус, Retry-After и время каждой HTTP-пробы.
- `summary.csv` — пересчитываемая сводка.
- `depth.png`, `rates.png`, `memory.png`, `latency.png` — графики.

Локальные журналы `source.log` и `worker-*.log` сохраняются оркестратором,
но исключены общим правилом `*.log` из Git. Проверяемые численные выводы
опираются на CSV и JSON выше. Рабочий набор памяти — cgroup usage минус
inactive_file, а не RSS. Нулевое значение источника после выхода означает
завершение контейнера.

Для пересчёта таблицы и графиков:

```bash
uv run python scripts/plot_backpressure_experiments.py docs/experiments/2026-10-21-final
```

Сценарий повторного запуска и выводы приведены в
[основном README](../../../README.md#измерения-backpressure-и-материалы-этапа-b).
